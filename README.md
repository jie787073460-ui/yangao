# yangao

面向设计师的 UI 还原度一键走查工具。上传一张设计稿和一张前端实现截图，工具会在本地自动对比视觉差异，并把问题直接标注在实现图上，方便设计师和开发快速对齐修改点。

## 核心作用

- 快速发现设计稿和实现图之间的可见差异。
- 自动在实现图上绘制红色标注框、编号和问题说明。
- 将同一个位置的多个问题合并成一组，避免一个元素被重复打满标注。
- 按严重、中等、轻微分类问题，帮助优先处理影响最大的差异。
- 导出带标注的 PNG、Markdown 修复清单和 JSON 数据。
- 所有图片处理都在本地浏览器完成，不上传到第三方服务器。

## 支持的检查范围

工具会按以下优先级检查可见元素：

1. 颜色：填充色、描边色、文字色、透明度
2. 尺寸：元素宽度、高度
3. 位置：元素坐标、元素间距
4. 文字：字号、字重、行高、字间距、对齐方式
5. 圆角：圆角半径
6. 阴影：颜色、偏移、模糊、扩散
7. 边框：宽度、样式、颜色
8. 图标：形状、大小、颜色
9. 布局：整体对齐、元素顺序

## 三种对比方式

- 实现图标注：默认模式，只在实现图上展示问题标注，适合直接验收和导出。
- 平铺对比：设计稿和实现图左右并排展示，适合人工快速扫一遍整体差异。
- 透明度叠加：把设计稿叠在实现图上，并可调整透明度，适合发现位置偏移、尺寸不一致、布局错位等问题。

## 不同机型尺寸怎么验收

实际开发截图和设计稿经常不是同一个设备尺寸。yangao 不会简单按原图像素硬比，而是先根据图片宽高判断对比模式：

- 如果两张图尺寸一致，按像素级方式检查。
- 如果宽度不同但比例接近，会进行响应式归一化，再检查元素相对位置、尺寸和视觉差异。
- 如果比例或裁切差异较大，会进入保守对比，只标出更有把握的问题，避免误报。

移动端顶部状态栏默认不参与验收，例如时间、信号、Wi-Fi、电量等动态系统信息会被忽略。

## 动态内容处理

文字默认按固定内容检查，适合验收标题、按钮、菜单、说明文案等不可变内容。

如果某些区域是动态数据，例如积分、数量、消息数、用户名等，需要通过页面标记、对比说明或手动忽略区域声明为动态内容。动态区域可以忽略内容本身，但仍会检查字体、颜色、位置、尺寸和容器样式。

## 导出能力

- 标注 PNG：左侧保留实现图原始尺寸并绘制标注，右侧展示严重和中等问题清单。
- Markdown 修复清单：按严重程度分组，适合直接发给开发修改。
- JSON：输出结构化问题数据，便于后续接入其他流程。

导出 PNG 默认只包含严重和中等问题，轻微问题保留在页面内查看，避免导出图过于拥挤。

## 安装和打开

把本目录作为 Codex skill 安装后，可以通过 skill 启动本地应用。

也可以直接在本目录运行：

```bash
python3 scripts/launch.py
```

启动后终端会输出本地地址，例如：

```text
yangao ready: http://127.0.0.1:4179
```

在浏览器打开这个地址即可使用。服务只监听 `127.0.0.1`，不会对外暴露。

## 使用建议

- 上传截图前，尽量保证设计稿和实现图是同一页面、同一滚动位置。
- 如果实现图来自不同机型，优先使用平铺对比和透明度叠加确认整体缩放关系。
- 对明显动态的数据，先用忽略区域或规则说明排除内容差异。
- 导出给开发时优先使用标注 PNG 和 Markdown 清单。

## 适用场景

- 设计走查
- 前端视觉验收
- 设计稿还原度检查
- 多机型截图对比
- 设计师和开发的修改沟通
